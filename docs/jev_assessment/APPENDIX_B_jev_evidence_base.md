# Jev / System One Models fact base (compiled 2026-09-21 from first-hand reads + search summaries)

Tags: [V] = TypeSafe's own claim or docs · [I] = independently measured by a third party · [S] = from a search summary of a page that could not be fetched (treat as second-hand) · [U] = unverified community listing.

## Identity and availability
- TypeSafe AI (San Francisco) came out of stealth 2026-09-15 with $40M seed; founder Diogo Almeida (ex-OpenAI). Jev = first "System One model", early access. [V/S]
- Hosted API only (POST /v1/systemone); no weights, no paper, no training details, no calibration curves published as of 2026-09-19. Also reachable via OpenRouter "Decisions API" (POST /api/alpha/decisions), Vercel AI Gateway, Cloudflare AI, Pydantic AI, LangChain. [I: vLLM issue #3970, souvikr/jev-test, scienthoon] [S: MindStudio RLCD post]
- Current release jev-1.13.0; aliases jev-latest / jev-preview MOVE when TypeSafe ships; TypeSafe recommends pinning once thresholds are tuned; response carries the versioned model id. Vercel gateway exposes no model version. [V/S; I: clownware/bouncer issue #54, scienthoon]
- TypeSafe states responses are not used for training; enterprise terms/DPA separate. [V/U]

## Interface (what it does and does not return)
- Input: "state" = string / JSON object / array (text only; English primary; test non-English). Questions are evaluated INDEPENDENTLY and in parallel against the identical state; adding questions barely changes latency. [V]
- Question types: Noul = probability (0–1) that a yes/no proposition is true (no separate confidence); Choice = one option of up to 255 with a probability per option + a confidence; Score = position on a 2–10 level scale with probability per level + confidence (score may fall between levels). [V]
- "Confidence" is a DERIVED value describing how concentrated the distribution is (flat → low). It is not an epistemic signal about whether the state contains the information needed. [V, gist reference; I: scienthoon unknowable-task result]
- Returns NO text, NO rationale, NO evidence spans or citations. "A number, not a rationale." Audited workflows need a generative model on top for explanations. [V; S: several reviews]
- Probabilities are quantized to 0.01 and are frequently exactly 0 or 1. [I: scienthoon]

## Limits and pricing
- 64k tokens per request (state + all questions); 32k for state + the longest single question (~150k English chars; dense numeric text tokenizes worse). Rate limits ~1,200 requests/min, 250k tokens/s (dynamic). [V/S]
- Pricing $0.042 per million input tokens, output free. [V]
- Latency: vendor 70–500 ms end-to-end; independent p50 ≈ 380–450 ms, p95 ≈ 540 ms; ≈ $0.000016–0.000017 per call in small tests. [V; I: themsquared, souvikr]

## Vendor-documented weaknesses ("Jev 1.13 jaggedness" page) [V/S]
- Does not count reliably (characters, occurrences, items in a long list); error grows with size. Recommendation: iterate in code, one Noul per candidate, sum in code.
- Arithmetic and DATE COMPARISONS: do them in code.
- Indirection: double negatives, "property of a property", multi-hop questions cost accuracy.
- Distracting context: accuracy falls as the state grows with content unrelated to the decision.
- Adversarial input: "State is data, and jev-1.13 does not treat it as hostile by default. Content written to adversarially steer the model — an injected instruction, a deliberately misleading framing, or text that argues for its own classification — can move the answer." "Do not treat the model as a security boundary."
- Explicit non-capabilities (reference): no research/external data, no explanation, no planning, no chaining (multi-step needs separate requests with code dependencies), semantic errors possible with high confidence.

## Vendor claims and their basis [V]
- 40–200x faster and up to 400x cheaper than frontier LLMs; the most-quoted 193.6x / 444.6x come from TypeSafe's own workflow evaluations and TypeSafe says they "sit at the higher end of real-world gains".
- ~68% accuracy on TypeSafe's 4-workflow benchmark, "close to mid-tier LLMs". The REFERENCE answers are the average of GPT-6 Astra and Claude Fable 5.1 answers → the benchmark measures agreement with two LLMs, not correctness.
- "Zero hallucinations" = schema-level only (cannot emit an out-of-schema value); TypeSafe's own 0% chart is labelled "not empirical" (follows from design). CEO on Hacker News: "It is possible to be wrong with high confidence – and all future models will be smarter and still have this possibility."
- RLCD ("Reinforcement Learning for Calibrated Decisions"): described only in intent (probabilities optimized against outcomes). No reward function, architecture, procedure or curves disclosed.

## Independent measurements [I]
1. scienthoon/jev-ood-calibration (2026-09-19; Vercel gateway; 900 rule-generated support tickets, 300 per type; 4,621 calls; $0.06; 0 failures):
   - Choice (queue): 89.0% acc, ECE 0.082, refit temperature 3.29 → severely OVERconfident.
   - Boolean (angry?): 91.7% acc, ECE 0.079, T 0.66 → UNDERconfident.
   - Score (priority) where the label depends on an organisational rule ABSENT from the text (unknowable from state): 44.7% acc (~chance), ECE 0.325, T 3.40, mean confidence 0.74 → "does not know it doesn't know".
   - Aggregate: 75.1% acc, ECE 0.107 = 4.4x the 0.024 noise floor. Public benchmarks (likely in-domain): OpenBookQA 94.2%/ECE 0.024; CommonsenseQA 88.1%/0.032; HellaSwag 86.1%/0.029. One item got probability 0.00 for the correct answer.
   - Conclusion: "calibrate per question, not per model"; a fixed 0.9 threshold's safety depends on question TYPE.
2. AnthusAI/Jev-Calibration (jev-1.13.0; 8,801 sentiment items; 60/40 split): raw Noul mean confidence 79.0% vs accuracy 72.3% (ECE 0.117, Brier 0.162); Choice 91.4% vs 76.1% (ECE 0.147). Platt scaling → ECE 0.052; isotonic regression → 0.008 (0.006–0.018 across variants); most of the benefit by ~200 labelled examples. Out of the box the confidence does NOT reliably represent accuracy; after isotonic recalibration on held-out labels it does.
3. themsquared/jev-benchmark (agent tool-call risk: readonly/destructive/privileged/exfiltration; 60 hand-labelled: 34 clear, 14 ambiguous, 12 adversarial): 91.7% overall (clear 100%, ambiguous 71.4%, adversarial 91.7%); p50 ≈ 422 ms, p95 542 ms; ECE 0.071; all 5 errors at confidence ≤ 0.785; none at 1.000; 50/60 predictions in the top bin. Author: confidence usable for routing, small n.
4. souvikr/jev-test (17 cases, 23 checks; jev-1.13 via OpenRouter): all checks passed; parity with Claude Opus 5 and GPT-5.6 Terra on these easy cases; median 452 ms; "3x faster than GPT-5.6 Terra, 7.5x than Opus 5; 35x / 190x cheaper"; adding structured criteria (what + examples) raised confidence 0.26 → 0.97 on ambiguous cases. Single run.
5. Phishing decomposition test (beri.net / xenospectrum; 2,000 emails) [S]: one holistic question → Jev 62.6% vs Claude Haiku 4.5 81.3%; five decomposed questions with weights fitted on 1,000 and scored on the held-out 1,000 → 95.0%. "Accuracy swings with how you ask."
6. vcjdeboer/jev-reliability (preregistered; jev v1.13.0; 100 determinism calls, 480 variance-decomposition calls, 80 answerability calls, 112 Noul calls; nested Bayesian variance model): variance from question PARAPHRASE ≫ perturbation ≫ repeat; phrasing, not random noise, is the largest error term; measures consistency only, "nothing about accuracy".
7. Legal corpus test (X article, 544 Spanish regional data-protection-authority resolutions; question: did the case originate as a complaint filed with the national agency and transferred?) [S]: 98.2% agreement with a hand-built deterministic rule; of 10 disagreements Jev right in 9; 4/544 fell in an abstention band; 1.33M input tokens, $0.056, 71 s, 0 errors.
8. Community entries [U]: DocJev 40/40 on a pilot, ~182 ms p50; Sniff Test 1/54 clean paragraphs flagged vs 37 for Haiku; BTK audit 1,204 pages, 4,816 judgments per run, $0.0048 per 12-query batch; CUA-S1-FORMS: a 706K-parameter specialist scores 99.7% on form-filling vs Jev 83.6% (narrow specialists beat Jev on narrow tasks).

## Ecosystem patterns relevant to a policy/authority product
- TypeSafe's own pattern: "questions describe judgments; code owns composition, thresholds, and side effects"; Observe → Judge (Jev) → Reason (LLM for ambiguous) → Act; escalate medium confidence to a human, low to a reasoning model; six-question suitability test (judgement, bounded, atomic, context-contained, fast-human, machine-consumed). [V]
- clownware/bouncer (Claude Code PreToolUse gate; MIT; 1 star; v0.2): DETERMINISTIC hard rules first (credential patterns, force-push, etc.) → Jev answers 7 policy questions on a 4KB-capped state → YAML thresholds; 0.40–0.60 uncertainty band → ask the human; observe mode; JSONL audit log; Brier score; calibration tables (86–100% accuracy at confidence ≥ 0.80) enforced as release gates. Hard rules were ADDED after the classifier missed high-confidence risks. "Not a security boundary"; partial classifier responses can escalate but never auto-approve; jev-latest silent drift is an open issue (#54). [I]
- souliane/teatree issue #4819 (design memo): use Jev where "the input is an artifact we generated and the output ranks or filters"; NEVER for authority/trust decisions (state carries injected content; provenance needs deterministic verification), deterministic checks/arithmetic ("a test result is a fact; a probability removes the loud failure"), or generation. Layering: deterministic matchers → typed judgments (advisory/additive only) → LLMs. Never grade with the same model; measure calibration per bucket; threshold asymmetrically. [I]
- vLLM semantic-router issue #3970: Jev's confidence "must not be treated as a label probability or a per-request correctness guarantee"; hosted-only lock-in; record model version; pin. [I]
- ~300–500 community projects within a week (awesome-jev lists); guardrails, code review, routing, extraction, agent approvals; compliance/legal use is thin (one motion-to-dismiss predictor; the DPA-resolution test). [U]

- Published prior art catalogued by the community: zero-shot classification as entailment (EMNLP 2019); the InstructGPT reward model (scalar head, one pass; co-authored by Jev's founder); RLCR "Beyond Binary Rewards" (ICLR 2026; Brier-score reward for calibrated confidence — the closest published analogue to RLCD); LLaDA masked diffusion (TypeSafe's GitHub fork suggests the parallel-answer-slot architecture); GLiNER/GLiClass encoder-family label scoring. Nothing in Jev's public surface is without a published precedent; the combination and the training recipe are what is proprietary. [I/U]
- Other independent evals [I/U]: jev-sec-bench prompt-injection detection 96.5% acc / ROC-AUC 0.9927 (662 messages); jev-rerank-bench nDCG@10 0.692 vs Cohere 0.691 (8 datasets); jev-spam-eval 0.9833 accuracy on 18,514 samples — matched a TF-IDF baseline; jev-use 82.2% agreement with Claude Opus over 454 judgments (89.5% excluding escalations); TypeSafe's own dashboard 61.7–76.0% accuracy across 4 workflows at 0.3–0.5 s per case; Near Here event validation 96% vs Mistral 84% on 50 cases; chess FEN-to-move: random; GLiNER2.5 comparison 0.910 AG News / 0.870 Banking77; agentjournal.dev on Japanese NLI: direct questions 0.9076 vs dimension-scored 0.8373, but 37.2% false positives vs 1.5% — decomposition trades accuracy for a different error profile.
- Evaluation harnesses exist for legal (LegalForecastBench, motion-to-dismiss) and SaaS schemas, but with NO Jev results published yet. There is still no independent test of Jev on long contractual or regulatory text beyond the 544-resolution extraction test [S].
- JevBench v1.2 (Benchmark Heaven, scored 2026-09-21; NOT affiliated with TypeSafe; 41 systems, 534 decisions incl. 220 hard; score = geometric mean of Intelligence, Calibration, Speed, Cost at 25% each): Jev 1.13.0 75.4; SemIf (Qwen3.5-4B) 74.7; djev (Maisa, diffusion-gemma) 74.3; Laya (421M) 70.1; open-alternative-jev (Qwen3.5-4B) 69.8; system-one-open 68.9. Six days after launch, open systems are within 1 point of Jev on the composite. openJev-verdict-2.0 (151M non-autoregressive) reports 77.10% acc, Brier 0.0636, ECE 0.0144 on a LocalLLaMA typed-decisions set, claiming to beat Jev and Laya there. [I/U]
- Architecture (community analysis, [S]): non-autoregressive single parallel forward pass mapping an encoder-style representation onto every declared answer slot at once; not iterative diffusion denoising. Closest published training analogue: RLCR (Damani et al., ICLR 2026, arXiv 2507.16806) — RL reward = correctness + Brier score; reported to improve calibration in- and out-of-domain without accuracy loss. TypeSafe's RLCD remains undisclosed.
- anisselbd/jev-phishing-bench (first-hand; published 2026-09-17; PhishNChips v5.2, 2,000 LLM-generated emails, 1,000 phishing with real malicious URLs + 1,000 legitimate incl. 333 false-positive traps; jev-1.13.0; Haiku 4.5 at temperature 0, no thinking) [I]:
  - Single holistic question, all 2,000: Jev 62.6% [60.5–64.7], AUROC 0.689, ECE 0.154; Haiku 81.3% [79.5–82.9], AUROC 0.837, ECE 0.097 (McNemar p<0.0001).
  - Five decomposed signal questions (domain mismatch, free hosting, lure, urgency, generic sender), logistic-regression weights fitted on 1,000 and scored on the other 1,000: Jev 95.0% [93.5–96.2], AUROC 0.982, ECE 0.027; Haiku asked the same five questions 93.2% (tie, p=0.063; Haiku AUROC 0.991); regex baseline 91.8%. Jev's best single signal alone 89.4% loses to regex. Decomposition helped Jev and slightly hurt Haiku (94.2% single signal → 93.2% composite).
  - Latency p50 Jev 239 ms vs Haiku 687 ms; cost per 1,000 emails $0.038 vs $0.462; decomposition run $0.04 vs $1.02.
  - Repeatability: Jev 2.2% label flips between two passes (max prob diff 0.15), 1.0% flips on 200 emails re-run 12 h later; Haiku 0.7% flips, 98% identical probabilities.
  - Caveats: synthetic bodies; URL-reputation ground truth; one system prompt per model (LLM recall ranged 27–96% by prompt alone).
  - Follow-up (issue #1): Qwen3-4B-Base + LoRA fine-tuned on 1,000 of the emails, 2 epochs, ~18 min on one RTX 4070 SUPER, temperature refit on 250: 97.4% accuracy, ECE 0.010, recall 98.8%, FPR 4.0% on a 500-email holdout, versus Jev zero-shot 62.6% / ECE 0.154 / recall 43.2% / FPR 18.0% on the same split. Supervised vs zero-shot, so not like-for-like — but it shows that ~1,000 labels for a STABLE declared predicate produce a cheap specialist that beats Jev by ~35 points.
- Customization and deployment [V/S]: TypeSafe does NOT fine-tune or LoRA-adapt Jev with customer data; every account uses the same weights; customization is only via the request (reference material in the state, rules/edge cases in each question's criteria, composition in code). jev-preview currently points to the same model as jev-latest. Hosted service in a single region; higher limits on enterprise plans via sales; no on-prem/VPC option published. Enterprise-readiness concerns raised in press (InfoWorld): security, data residency, SLAs, vendor dependency on an early-stage vendor.

## Addendum 2 (from the 17-agent verified sweep, 2026-09-21; full sheet at jev_fact_sheet_wf1.md). Tags: [I] independent, [V] vendor, [U] unverified.
### Abstention and unknowability (decisive for Problem D)
- WITHOUT an explicit abstain option Jev never abstains: 0/30 out-of-scope inputs flagged (priorbench); accuracy on unanswerable items 0.950 → 0.000 with stereotype rate 0.79 at confidence 0.79 (jujumilk3); labels that depend on a rule absent from the text answered at mean probability 0.74 (scienthoon). [I]
- WITH an explicit "not determinable" option it abstains well on GENUINELY UNANSWERABLE items: 95% abstention on 300 unanswerable KoBBQ items, ECE 0.023 at a 0.024 noise floor (jujumilk3); CLINC out-of-scope median probability drops 1.00 → 0.54, but 15% still ≥ 0.9 (Running-Dolphins). [I]
- It does NOT abstain when the answer requires an inference step that is missing: "unknown" chosen 0/6 for missing-link chains at every length (RINNECODER); an UNCERTAIN option went unused in 265 calls (pi-jev-context). The vendor's own guidance is to add a no-match option AND a separate evidence-presence question; a presence question "catches what confidence cannot" (vcjdeboer). [I/V]
- Jev answers from PRIORS: with the question's supporting state removed it still scores 0.38–0.46 versus ~0.15 chance (jujumilk3). A document-grounded predicate may be answered from world knowledge rather than from the document. [I]
### Confidence, thresholds, determinism
- Confidence is empirically indistinguishable from the normalized entropy of the returned distribution (AUROC 0.706 vs 0.705, Janus); TypeSafe's docs call it "a margin, not a probability that the answer is right", approximate it as (k·max_p − 1)/(k − 1), and a second-hand written answer says the formula is "not published, and it drifts across model versions". [I/V]
- Wrong at probability 1.00 is routine, not exceptional: 6 of 102 CLINC items (ickma2311); 129 Web-of-Science rows at 1.00 were only 76.7% accurate (Janus); 11/191 and 14/187 wrong at p=1.00 (Running-Dolphins). themsquared's "never wrong at 1.000" was n=60, where even a perfect model scores ECE ≈ 0.045. [I]
- Thresholds do not transfer: optimal threshold 0.67 → 0.37 between Banking77 and Web of Science ("DO NOT ROUTE" verdict on the latter); Noul and two-option Choice framings of the same predicate differ by 0.125 mean and complements sum 0.71–1.42; Spanish ECE doubles 0.057 → 0.101; fewer than ~100 labelled rows per question cannot fit a threshold (jevcal). [I]
- Not deterministic: 50 byte-identical requests → 15 distinct answer sets (SD 0.001–0.015); 2.2% label flips on re-run; a borderline Noul ranged 0.38–0.52 across 20 calls, crossing a 0.5 cutoff 6 times. Argmax is stable on clear items (0 flips in 400 with option order reversed). Audits need a pinned version, the logged `model` field, and tolerance bands. [I]
- Question wording: paraphrase flipped 12.5% of answers in a pre-registered study (vcjdeboer) and moved probabilities 0.164 mean / 0.52 p95 on a hard task (yodablocks); a criteria label "touches credentials" made read-only inspection escalate at 0.88 (typesafe-ai/skills #5). "jev-1.13 answers the question you wrote, not the one you meant" [V]. [I]
### Long inputs and distraction
- No independent test of Jev on a 100-page contract or filing exists. Well below the 32k cap discrimination degrades: in a ~12,600-token state, rows in slots 24–39 drifted probabilities by 0.42 and 159/360 rows fell into the 0.3–0.7 band (yodablocks); conflicting records buried mid-state (7.5k–14.7k tokens) were found 1/6 and 0/6 times (RINNECODER). Oversized requests are rejected with 400 and still billed (harn #8540). JSON tokenizes at ~3 chars/token. [I]
- Vendor jaggedness understates numeric ability: number comparison and date ordering scored 99.6% across 13 designs in a pre-registered 5,721-call study (priorbench); but arithmetic degrades with answer position (95/108 first vs 62/108 last, RINNECODER) and letter counting is 117/216. Multi-hop reasoning is absent. [I]
### Adversarial state
- A `// satisfies REQ-AUTH-02` comment in code can skew a compliance judgment (nozomi-koborinai/jev-spec PR 13); the vendor states state is not treated as hostile by default. No red-team numbers exist for self-describing clause language ("this provision complies with §X"). [I/V]
### Economics, reality-checked
- Latency versus properly constrained LLMs is ~3x, not 100x: 2.9x vs Haiku 4.5 wall-clock, 6.5x vs Opus 5, parity with GPT-OSS-120B Nitro (283 vs 293 ms), SLOWER than local GLiNER (~44 ms) and Laya/Von (46–55 ms). Service time ~76 ms; network floor 160–200 ms; throughput saturates near 11 req/s. [I]
- Cost versus cheap chat models is 1.4–1.7x per decision (mistral-small-3.2, gemini-2.5-flash-lite); 12–323x only against frontier models at list price. [I]
- Accuracy: frontier LLMs beat Jev on JevBench intelligence and calibration (GPT-5.6 Luna 96.8/89.8, DeepSeek V4.1 Flash 96.1/96.7 vs Jev 90.4/82.7); Jev is #1 on the composite only through the speed and cost axes, and #5 on intelligence alone. A few hundred labels plus logistic regression beat Jev on accuracy on every dataset tested (bge-small + LR 0.933 vs 0.832). Jev beats clean zero-shot NLI encoders by +0.05 to +0.13 and holds under distribution shift (−1.0 pt vs −25.7 for a small encoder). [I]

- Sweep inference (not a sourced fact): typed/calibrated decision endpoints become a standard SKU at gateways and at least one hyperscaler within ~3–9 months; open models close the routine-classification gap in the same window.
### Enterprise readiness
- Hosted-only, US-hosted, no EU region, no on-prem/VPC/edge "now or planned", closed weights, zero-data-retention enterprise-only, no subprocessor list, no public SLA (status page 99.854% over 90 days), 529 "system_overloaded" on 5 of 6 calls for one tester in launch week; official SDK default timeout 10 s; a customer-agreement clause reportedly restricts publishing performance numbers (unverified). [V/I/U]
